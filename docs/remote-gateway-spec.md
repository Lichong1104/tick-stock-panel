# Spec：远端网关 + Codex 插件

术语以 [`remote-gateway-plan.md`](remote-gateway-plan.md) §2 的术语表为准（面板 / 网关 / 档位 /
订阅 / 双池计量 / 票据 / 复权口径基准 / 口径指纹）。决策编号 D1–D7 指该文档 §3。
本仓库当前没有 ADR 目录，D1–D7 在本改造范围内**起 ADR 的作用**，实现时不得绕过。

## Problem Statement

现在要用这套系统，每个使用者都得自己凑齐两样东西：一个行情数据源的凭据，一个 LLM 的凭据。
凑齐之后还得在本地把面板跑起来，数据抓取和指标计算全部压在自己的机器上。

由此产生三个问题：

1. **用不到。** 系统能力只在面板的界面里，Codex 会话里用不上。想让 AI 助手帮着查行情、
   跑分析，得人来回复制粘贴。
2. **门槛高且重复。** 每个用户各自申请数据源 key、各自配 LLM base_url 与 api key。
   同一份数据被反复抓取，同一份凭据被反复配置。
3. **没法按服务供给。** 没有任何地方能表达「这个用户买了多少额度」。
   既不能限制用量，也不能按档位区分服务，更没有计量的落脚点。

## Solution

引入一个**远端网关**，由它统一持有上游凭据、统一做计量与授权。使用者登录后，
按自己的订阅（档位）获得行情服务与 LLM 服务。

系统以一个 **Codex 插件**交付：装一次，在 Codex 里就能用行情与 LLM 两类能力，
不用自己配任何上游 key。插件内含两个 MCP server（行情、LLM），因为这两类资源的
授权面与计量池不同。

面板本身**保持单用户、本地**不变——它的能力、界面、数据流、指标、策略、回测全部照旧。
变的只有一件事：它的行情与 LLM 调用改从网关走（D1、D2）。

计量口径：LLM 按 token；行情按**月**，且**历史池与实时池分开**（D4）。

复权仍然由消费端自算：网关只给事实层（原始价）和因子层（单事件比值），
不下发上游推算好的前复权价（D3）。派生数据上落一个**口径指纹**，
使因子口径变化时缓存能被判定失效，而不是继续供应旧口径结果（D7）。

## User Stories

**安装与登录**

1. 作为 Codex 用户，我想要用一条命令把插件装进 Codex，以便不用手动拼配置文件。
2. 作为 Codex 用户，我想要在 Codex 里一条命令完成登录，以便凭据自动落到正确位置。
3. 作为 Codex 用户，我想要登录后不必再单独配置数据源或 LLM 的 key，以便装完就能用。
4. 作为 Codex 用户，我想要在凭据失效时得到一条明确的重新登录提示，以便知道该做什么而不是看到一串 401。
5. 作为 Codex 用户，我想要登出后本机不再留存可用凭据，以便在共用机器上不留后患。
6. 作为 Codex 用户，我想要插件升级后不必重新登录，以便凭据不会因升级被清掉。
7. 作为脚本/自动化使用者，我想要用 API key 而不是交互式登录，以便无人值守跑批。
8. 作为脚本使用者，我想要 API key 与我的交互式登录共享同一份订阅与额度，以便两边用量合在一起算。

**行情服务**

9. 作为使用者，我想要在 Codex 里取日线数据，以便不问人、不打开面板就能做分析。
10. 作为使用者，我想要取分钟线与全量分钟数据，以便做日内研究。
11. 作为使用者，我想要取复权因子，以便自己按统一口径算前复权价。
12. 作为使用者，我想要取实时快照，以便在盘中看当前状态。
13. 作为使用者，我想要取五档盘口，以便判断短期流动性。
14. 作为使用者，我想要取财务数据，以便做基本面判断。
15. 作为使用者，我想要取标的清单，以便知道系统覆盖了哪些代码。
16. 作为使用者，我想要在请求某个数据集而我的档位不含它时，得到一条说明「该数据集不在当前档位」的明确错误，以便知道这是授权问题而不是数据问题。
17. 作为使用者，我想要在某个数据集上游暂时不可用时得到明确失败，以便**绝不会**在不知情的情况下拿到另一套口径或另一个来源的数据。
18. 作为使用者，我想要侧栏那四只核心指数的取值与档位无关，以便它们始终可用、始终一致。
19. 作为使用者，我想要同一个数据集在面板里和在 Codex 里返回同一份内容，以便两处结论不会打架。
20. 作为使用者，我想要重复请求同一段历史数据时不必重复付额度，以便不因重试而被扣费。

**LLM 服务**

21. 作为使用者，我想要在 Codex 里直接用 LLM，以便不用自己申请 key。
22. 作为使用者，我想要按我的档位看到可用模型清单，以便知道我能用哪些。
23. 作为使用者，我想要在请求档位不含的模型时得到明确的档位错误，以便区分「没权限」和「服务故障」。
24. 作为使用者，我想要流式输出，以便长回答能边生成边看。
25. 作为使用者，我想要 LLM 用量按 token 计量并可从界面查询，以便知道还剩多少。
26. 作为面板使用者，我想要面板里的 AI 助手继续照旧工作，以便我不必为了这次改造改我的使用习惯。

**订阅与额度**

27. 作为订阅者，我想要知道我的档位覆盖哪些数据集、哪些模型，以便判断是否需要升档。
28. 作为订阅者，我想要分别看到历史池与实时池的剩余额度，以便知道是哪一类用超了。
29. 作为订阅者，我想要在用完额度时得到明确提示，以便知道是等下一个周期还是升档。
30. 作为订阅者，我想要实时请求不会消耗历史池额度，以便盯盘不会挤占我的回测额度。
31. 作为订阅者，我想要超过额度后请求被拒绝而不是被静默降级，以便我的结果始终可信。
32. 作为订阅者，我想要多个客户端（面板、Codex、脚本）共享同一份额度，以便用量口径唯一。

**复权口径**

33. 作为研究者，我想要网关只提供原始价与单事件因子，以便我算出的前复权价在跨数据源时口径一致。
34. 作为研究者，我想要因子明确是单事件比值而非累计值，以便不会把累计因子当单事件用。
35. 作为研究者，我想要网关拒绝透传上游已经算好的前复权价，以便我拿到的永远是事实层。
36. 作为研究者，我想要因子口径变化后派生数据能被判定失效，以便不会拿旧口径的回测结果当新口径结论。
37. 作为研究者，我想要口径变化后的重算是一次显式操作并给出明确进度与失败原因，以便出问题时能定位。
38. 作为研究者，我想要涨跌停判断继续使用原始价，以便复权改造不影响既有交易语义。

**面板侧**

39. 作为面板使用者，我想要面板继续是单用户本地应用、认证仍是单密码，以便这次改造不改变我的部署方式。
40. 作为面板使用者，我想要面板的行情读取仍然经由既有能力查询与数据集接口，以便指标、策略、回测代码一行不用改。
41. 作为面板使用者，我想要面板的通用界面里不出现档位、订阅、额度这类词，以便面板仍然是数据源中立的产品。
42. 作为面板使用者，我想要面板在网关不可达时给出清楚的连接失败提示，以便能区分「网关了」和「数据没有」。

**网关运维**

43. 作为网关运营者，我想要为账号开通与变更档位，以便供给服务。
44. 作为网关运营者，我想要吊销单个凭据而不影响该账号的其他凭据，以便处理凭据泄露。
45. 作为网关运营者，我想要限流在多实例部署下依然准确，以便扩容不会静默放宽限制。
46. 作为网关运营者，我想要额度计数以数据库为准而不依赖进程内存，以便重启或多实例不会丢计数或重复计数。
47. 作为网关运营者，我想要看到某账号在两个池上的消耗，以便处理用量争议。
48. 作为网关运营者，我想要上游凭据只存在于网关侧，以便客户端泄露不会牵连上游账号。
49. 作为网关运营者，我想要在某个上游故障时只影响对应数据集，以便其他数据集继续服务。

**插件与扩展作者**

50. 作为插件作者，我想要插件以清单声明远端 MCP server，以便用户装完即用。
51. 作为插件作者，我想要同一个插件内声明两个 MCP server 且各自独立声明凭据，以便行情与 LLM 的授权互不牵连。
52. 作为插件作者，我想要在一个未证实会被运行时采纳的清单字段之外还有一条显式注册步骤作为兜底，以便安装一定生效。
53. 作为数据源插件作者，我想要在网关侧沿用既有的能力声明与数据集协议来实现新数据源，以便这次改造不发明第二套插件机制。
54. 作为数据源插件作者，我想要新增一个数据源时面板侧零改动，以便扩展成本不随数据源数量增长。

**安全与合规**

55. 作为使用者，我想要一个账号的行情请求不会返回另一个账号的任何数据，以便多租户边界可信。
56. 作为使用者，我想要我的 API key 只以哈希形式存储，以便库被读取也不等于凭据泄露。
57. 作为安全负责人，我想要凭据具备有效期，以便长期凭证不是唯一形态。
58. 作为安全负责人，我想要日志与错误响应不包含凭据、完整配置或他人数据，以便排障不制造新的泄露面。
59. 作为安全负责人，我想要额度判定在服务端权威执行，以便客户端无法通过改本地状态超用。

## Implementation Decisions

**新增：网关服务**

一个独立的远端服务，包含五块职责：票据签发与校验、订阅/档位解析、双池计量、
数据集路由与代理、LLM 代理。它是唯一持有上游凭据、唯一有用户模型、唯一有数据库的一侧（D1、D5）。

**网关侧复用既有 provider 协议**

数据源插件体系整体上移到网关：网关侧的 provider 继续以「能力声明 + 标准化数据集方法」
为契约，能力矩阵继续是路由的单一权威，缺能力时继续 fail-closed（D2，CONTRIBUTING §4）。
面板侧现有 provider 实现可直接作为网关上实现同一协议的参考，不发明第二套插件机制。

**面板侧：只新建一个远端 provider**

它实现既有 provider 协议，把每个数据集请求转发给网关。既有调用方
（日线、复权因子、分钟、全量分钟、实时、五档、财务、标的清单）全部不改——
它们本来就走能力查询与数据集接口。能力来源由网关下发，面板不再自己汇总裁决。

**面板侧：LLM 客户端构造点改指向网关**

面板的 LLM base_url 本来就是可配置项，因此改造集中在客户端构造与出站两处。
凭据从「用户自己的 api key」换成「网关票据」。流式路径同样改指网关。

**移除 codex_cli provider**

LLM 全部远端化后，本地 codex 命令行 provider 不再有意义，从可选 provider 中移除（Q12 决定）。

**Token 记录扩展**

既有 token 体系保留（前缀规则、仅存哈希），但记录需补两个字段：**归属账号**与**有效期**。
这是扩展而非替换；既有字段与语义不变（D5）。

**票据**

HMAC 签名的无状态票据，claims 覆盖：账号、档位、作用域、过期时间。任何实例可独立校验，
不依赖粘性会话。作用域区分行情与 LLM 两面，与两个 MCP server 一一对应（D5、D6）。

**计量**

- LLM：输入 token 与输出 token 分开记。
- 行情：按**月**，**历史池**与**实时池**各一个独立计数桶，每次请求带池标签（D4）。
- 计数以数据库为权威；进程内计数器不作为判定依据（D5）。
- 超额度拒绝，不降级。

**档位配置表**

档位是一张配置表，同时给出三组数值：LLM token 额度、历史池月度额度、实时池月度额度，
以及该档位可见的数据集集合与模型集合。**具体档数与数值不在本 spec 内**。

**复权契约**

网关的复权因子数据集契约收紧为：**单事件比值、非累计**，并显式拒绝透传上游的累计因子
或已推算的前复权价（D3）。消费端继续按既有统一公式自算投影层。
涨跌停判定继续使用原始价（CONTRIBUTING §3.2，不受本改造影响）。

**口径指纹**

派生层（复权后的 enriched、回测矩阵磁盘缓存）需要一个显式的**口径指纹**标记，
表达「这份数据是用哪套口径算出来的」。读侧先校验指纹，不匹配即 fail-closed 重算。
实现形态沿用既有「落一个可读基准标记」的先例。这解决的是一个**静默错误**面：
现状下因子口径变化而派生数据未重写时，内容 generation token 不变、缓存版本校验也通过，
于是旧口径结果被继续供应（D7）。

**数据契约与 schema 变化**

- 网关新增：账号、订阅/档位、token（含归属与有效期）、双池用量计数。
- 既有 token 记录：新增归属与有效期两个字段，向后兼容（旧记录视为无归属、不过期）。
- 不改动行情历史数据本身的任何口径与 schema。

**能力层中立（硬约束）**

档位、订阅、额度属于**网关词汇**，不得出现在面板通用界面与通用 API 响应中。
面板看到的仍然只是「某数据集可用/不可用」。

**实时指数固定契约不受档位影响**

核心四只指数是产品级固定契约、不开放配置。远端化不得把它变成按档位可变的集合，
也不得让它参与档位过滤。

**插件交付形态**

一个 Codex 插件，内含两个 MCP server（行情、LLM）。传输只使用 **streamable-http**，
端点必须 HTTPS（仅本地回环允许 HTTP）。凭据同时支持 `api_key` 与 `oauth`；
OAuth 必须按**公共客户端**设计（PKCE，或支持 DCR/CIMD），因为清单层没有存放 client secret 的位置（D6）。

**安装步骤必须双保险**

因为「插件捆绑的远端 MCP 条目是否被运行时采纳」尚未证实，
安装流程在清单声明之外**必须**包含一条显式的 MCP server 注册步骤。
在真机验证证明清单足以生效之前，不得省略。

## Testing Decisions

**好测试的标准**

只断言**外部行为**：请求进来、响应出去、以及可观察的副作用（计数变化、拒绝发生）。
不断言内部实现细节（不数内部调用次数、不测私有函数、不绑定内部数据结构）。
对于金融数据，断言的重点是**口径正确**与**失败可见**，而不是「跑通了」。

**接缝（三条，已与用户确认）**

1. **面板 ↔ 网关·行情：数据集边界。** 测试打在既有 provider **能力查询与数据集实例化**上。
   这是全仓库行情数据的唯一咽喉，所有调用方（日线/因子/分钟/全量分钟/实时/五档/财务/标的）
   都经它。远端 provider 是**新增一个实现**，所以这里测一次等于覆盖十个调用方。
   **不新建接缝。**
2. **面板 ↔ 网关·LLM：客户端构造点。** 测试打在既有的客户端构造与出站两处，外加流式路径。
   它同时是 token 计量的挂点。
3. **网关自身：HTTP API 面。** 票据校验、档位判定、双池计数、数据集路由、LLM 代理
   全部经此进出。上游以 provider **假实现**替换——**与接缝 1 是同一个协议**，
   因此那套先例直接复用。

**为什么不合并成一条接缝。** 行情与 LLM 是两种资源：计量池不同、授权面不同
（两个 MCP server 正因如此拆分）。强行统一会把双池一致性藏在假一致性后面，
反而无法断言「实时请求不消耗历史池」。三条中，接缝 1 与 2 共用同一个出站传输
（票据注入与错误映射），传输逻辑只测一次。

**被测模块**

- 网关：票据签发/校验、档位解析、双池计量、数据集路由、LLM 代理、Token 归属与有效期。
- 面板：远端 provider（能力来源、数据集转发、fail-closed）、LLM 客户端构造与出站、口径指纹读侧校验。
- 契约层：复权因子数据集的单事件语义（拒绝累计因子与前复权价透传）。

**先例（同类测试）**

- 行情接缝：分钟 K 路由测试、能力矩阵测试、能力增补测试、全量分钟能力测试、自定义五档 provider 测试。
- LLM 接缝：AI provider 测试。
- 复权重算回归锚点：既有的管线容量测试（已覆盖「全量重算 enriched」入口）。

**必须覆盖的断言**

- **双池隔离**：一次实时请求只减少实时池；一次历史请求只减少历史池。
- **fail-closed**：未知数据集、能力缺失、上游故障 → 明确失败，**绝不**静默换源或换口径。
- **档位边界**：档位不含的数据集与模型 → 档位错误，而非数据错误。
- **口径拒绝**：网关收到/接到累计因子或前复权价时拒绝，不落库、不透传。
- **口径指纹**：因子口径变而后派生数据未重写 → 读侧判定失效并重算；指纹一致 → 命中缓存。
- **多租户隔离**：账号 A 的请求不可能返回账号 B 的数据。
- **额度权威性**：重启或多实例下计数不丢失、不重复；客户端本地状态无法影响判定。
- **能力层中立**：面板通用界面/通用 API 响应中不出现档位、订阅、额度词汇。
- **实时指数**：核心四只指数的可用性与取值不受档位影响。
- **票据边界**：过期票据、被吊销凭据、时钟偏差下的行为明确。

**不得作为业务验证的**

「登录成功」「扩展已加载」「接口返回 200」不是业务验证。测试必须断言真实的
数据集内容/拒绝行为/计数变化/失败隔离。

**批量回算的测试方式**

口径指纹落地需要一次批量重算。测试**不得**跑全市场真实数据；
以既有的容量测试为锚点，用小规模夹具断言「指纹写入 → 读侧失效 → 重算 → 指纹一致 → 命中」这一链路。

## Out of Scope

- **档位的档数与每档具体数值**，以及定价、计费周期、支付与开票。档位只以配置表形态存在。
- **面板侧的多租户改造**：不引入用户维度、不做注册/登录/支付/账单界面（D1）。
- **改写历史行情数据口径**：远端化只改数据来源，不改口径定义。
- **CORS 文档与实现不一致**（文档声称存在 `OPEN_API_CORS_ORIGINS` 白名单，实际是通配）。
  它与本改造正交，需单独决策，不夹带进本次 diff。
- **具体宿主/云选型、TLS 证书签发与续期流程、域名与部署拓扑**。
- **新增具体数据源**：本改造只把既有插件机制搬到网关侧，不新增源。
- **面板内既有会话的搬迁实现**（落地前需单独确认，见 Further Notes）。
- **上游升级兼容的自动化工具链**。

## Further Notes

**一条未闭合的技术风险。** 「插件捆绑的远端 MCP 条目是否会被 Codex 运行时采纳」在一次一手
调研中未能确认。因此安装步骤被定为**双保险**（清单声明 + 显式注册）。这是一个实现期
必须真机实测收口的事项：在任何证明清单足以生效的证据出现前，不得删掉显式注册步骤。
详见 [`codex-plugin-and-remote-gateway.md`](codex-plugin-and-remote-gateway.md)。

**执行期必须各自二次确认的操作**（CONTRIBUTING §13：不自动执行批量数据覆盖、删除、迁移）：

1. **全市场批量回算 enriched**（口径指纹的落地动作）。这是本次唯一的批量数据覆盖操作。
   既有入口是「全量重算 enriched，不取数、仅基于已有日线与复权因子重算」，
   其全量模式已拒绝覆盖缺失的既有日期分区。回归锚点见 Testing Decisions。
2. **移除 codex_cli provider**。
3. **既有会话搬迁到 Codex 侧**。

**性能数据不得虚构。** 全市场 enriched 重算**没有**直接实测数字。仓库内只有邻近代量
（指标计算在百万行量级的耗时、延长历史后的行数规模、日线全量同步的成本说明）。
这些**不得**被当作 enriched 全量重算的实测耗时使用。需要数字时实测。

**术语冲突提醒。** 仓库里有两个同名不同义的 `capabilities` 模块：一个是运行时探测
上游当前授予了什么，一个是设置页展示的能力路由矩阵。本 spec 提到的「能力矩阵」
**一律**指后者。远端化会同时触碰两者，混用会让改动范围判断完全错掉。
